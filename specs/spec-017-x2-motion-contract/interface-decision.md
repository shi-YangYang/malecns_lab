# 下一阶段 X2 最小动作接口决定

状态：设计已明确，代码尚未实施。仅限当前官方仿真；本文件不表示 MaleCNS 闭环已接通，也不授权真实设备动作。

## 第一版动作范围

神经侧先提供 `STOP` 或 `FORWARD` 意图，由独立适配器负责 ROS 发布与反馈。`FORWARD` 采用本次已经运行过的 MC 目标值 `(0.2, 0, 0)`，记录为 **MC 目标**，不把它叫作实际 0.2 m/s。不根据一个点的实测比例换算任意速度。后退、横移、转向、升降、滚转与俯仰请求第一版明确拒绝并归零；不静默丢弃 BodyVelocity 的未支持分量，不改已有序列化契约。

接口必须分别保留：神经意图及有效期、实际发往 MC 的目标、发布时刻、当前输入源、MC 模式与直立状态、里程计及其接收年龄、实测运动与停止结果。动作意图与持续 50 Hz 发布解耦，不要求完整脑以 50 Hz 完成计算。

## 前进与停止条件

- 前进前：当前仿真连接有效，里程计与 MC 状态新鲜，机器人直立，STAND/LOCOMOTION 状态适合动作，已注册自定义输入源并确认其控制权。启用必须显式，不因实例化或离线测试自动动作。
- 前进中：意图必须带有有界有效期，单次运行不超过已经验证的 5 秒窗口；过期、取消、无效数值、反馈过期、失去控制权或姿态异常都转入持续发送零速度。有效期和反馈年龄阈值需在实施中作为独立参数，不与 MC 输入源的 1000 ms timeout 混用。
- 停止中：持续发布零速度，不能仅调用 clear_velocity 后立即销毁 ROS 节点。等待新鲜反馈同时支持直立、STAND、水平低速持续窗口，再返回“已稳定停止”。
- 第一版可用的观测判据：水平速度低于 0.02 m/s 持续至少 1 秒，并且整个确认窗口 MC 都处于 STAND、body_status 为直立；位置变化作交叉核对。阈值是待实施和验证的判据，不是已有安全保证。不能把 LOCOMOTION 中第一次低速持续 1 秒当作完成，因为本次后续模式切换还出现姿态调整。
- 等待超时或断流：结果为“停止未确认/反馈不可用”，不能回报成功；按独立有界退出策略处理。官方消息超时机制是第二层保护，未做断流实测前不能用文档替代自己的停止验证。

## 距离与范围

停车依据完整观察到的最远位置与最终稳定状态，不能只看最终净余程。当前单次结果只能作为仿真计划的参考，不能承诺固定停车距离，不能把其直接用在真机避障距离中。后续若加入距离目标，应基于新鲜里程计做外层反馈与提前归零，独立验收终点偏差和超调。

首个后续实现交付：一个默认不动作、可注入假时钟和假传输的适配器，加上状态过期、意图过期、归零持续发布、STAND 后稳定确认的定向检查；然后才在 GPU 仿真做一次有界端到端验证。第一版无需先改 MC 策略、训练模型或追求全链路 GPU。
