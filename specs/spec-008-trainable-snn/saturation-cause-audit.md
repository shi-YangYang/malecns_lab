# 前进饱和、方向错误与大梯度：只读原因审计

状态：2026-10-19 只读诊断完成；不是修复实施或独立验收。不运行模型、不加载完整图、不导入 Torch、不改变旧实验。派生脚本及逐窗数据：`data/saturation_audit_20261019/analyze_saved.py`、`saved_analysis.json`。输入为 CPU 第 1–60 窗及 MPS 第 61–160 窗已保存 `evidence.npz` 的小型特征、参数、梯度和动作数组；报告包含每份输入 SHA256。以下 logit/导数为将保存数组升至 float64 的局部代数解释，不是重新运行完整网络，也不主张与 MPS 末位逐位相同。

## 已定位的事实

### 1. 没有发现前进坐标符号接反；错误是学习输出与教师目标不一致

`learning/follow_task.py:61–65` 明确教师 `vx=0.7*(distance_m−1.5)`：太远前进，太近后退。`drones/follow_env.py:131–143` 将正 vx 沿机身正前方积分，`learning/neural_policy.py:294–296` 将网络第 0 行直接放入 `BodyVelocity(vx=...)`，网络输入不接收几何真值。两个教师来源和保存标签没有相反的符号约定。

例如 forward 场景 4.4s 的保存真值距离 1.4268012836662138m、距离误差 −0.07319871633378616m，教师 vx 为 −0.05123910143365031m/s，符号与公式一致。对应第 63 窗网络输出 +0.3000000119m/s。因此不能把修复写成反转 vx，也不能用教师公式绕过连接组。

完整训练中，combined / forward / yaw 分别有 44 / 43 / 35 帧前进方向与教师相反。vertical 的前进标签始终为正，不适合用来证明前进换向已经学会。

### 2. 前进通道已经进入“纠正梯度为零”的数值饱和

源路径为 `neural_policy.py:252–255` / `mps_policy.py:116–119`：

`x=(mean_DN_voltage+52)/7; z=W*x+b; action=axis_scale*tanh(z)`。

损失 `mps_window.py:44–50` 为归一化动作 MSE；CPU 对应契约完全相同。因此某轴的 logit 梯度含有乘子 `1−tanh(z)^2`。保存的前进权重梯度在 **43–80、83–120、122–160，共 115/160 窗精确为零**。43–60 窗在 CPU 上就已经发生，不能归因为迁移 GPU 或 MPS 稀疏浮点差异。

### 3. 输入到线性读出的尺度、初期限幅标签和 Adam 动量共同把 logit 推入饱和

`(v+52)/7` 只按静息到阈值的差值换单位，**不限制或标准化输入幅度**。完整 160 窗保存的 DN 半窗均值最低为 −589.60376mV；稳定段归一化特征 L2 约 480–497，而非约 1。第 26 窗 x 范围 −73.3652 至 +0.9312，均值约 −3.94、标准差约 8.6。每帧读出有 2628 个特征，逐参数 Adam 步长累积成很大的 logit 变化。

保持每窗保存特征不变，仅代入真实更新前后读出，前进 logit 的变化：第 1 窗第二帧 +0.6651；第 2 窗 +0.9606/+1.0224；第 3 窗 +0.7969/+0.7869；第 4 窗 +0.6525/+0.6483。第 5 窗已超过 3，第 25 窗超过 8。

combined 最初 10 帧标签处于 +0.3 限幅；对于 tanh 读出，精确 +1 的归一化目标数学最优在 logit→+∞。随后标签开始回落，第 6–40 窗前进“当前梯度与实际参数增量内积”均为正，即该窗局部一阶方向仍是上升方向。Adam 的历史动量可以造成这种现象，并不表明 Adam 实现算错。第 20–40 窗两个教师 vx 都已经为负，读出仍使同特征 logit 增加。

此外，三个读出轴共用一组范数裁剪（`training_math.py:33–50`）。第 26 窗各轴梯度 L2 约 `[0.0001411, 11.0155, 47.5562]`：其它轴主导整体读出裁剪，已微弱的前进纠正进一步缩小。最终完全为零后，调裁剪阈值无法恢复它。

### 4. theta 大梯度与前进饱和是不同问题

第 1 窗 theta 原始梯度 L2 已为 7.78556e31；第 60 窗 2.86199e30；第 160 窗 9.76024e29。后两窗 vx 读出梯度已经为零，说明巨大 theta 梯度仍可由升降/偏航等其它梯度通路产生，不能把它全归咎于前进通道。

第 160 窗前 10 个 theta 分量占平方范数 97.68%；第 1 窗为 99.71%。全组裁剪让少数分量决定缩放尺度，既有记录中的下溢是真实后果。裁剪保证更新有限，不等于解决反向传播的条件问题。

静态路径：动作损失→读出→两个半窗 DN 均值→1000 个连续神经步→延迟完整图传播→按突触前类型共享增益。`brain/trainable.py:62–80` 的代理导数是 `1/[scale*(1+|distance/scale|)^2]`，scale=1mV；`mps_trainable.py:162–177` 的阈值/reset/refractory 判定 detach，延迟 spike 路径保留完整全细胞伴随。`mps_recompute.py:40–53` 每 50 步重算只节约激活内存，没有缩短反向图。

在活动且未触发 reset 的局部，电压/电流的线性化含 `a≈0.995`、`b≈0.9802`，但整个递归块还含 `W * gain * surrogate_derivative` 与 18 步延迟反馈。单个导数≤1、gain∈(0.5,1.5) 并不能保证该完整状态 Jacobian 收缩。因此**长时间递归代理梯度放大是强候选**；目前未保存逐时刻伴随，不能据此宣布已经找到某类神经元或某条边的因果错误，也没有证据证明 sparse backward 转置算错。

## 最小修复候选及验证顺序

### A. 前进纠正：保留执行端 tanh，修复训练目标的梯度失效

优先在新实验身份中把优化损失改为稳定的 soft-label logit BCE：

- `y=teacher_target/axis_scale ∈ [-1,1]`；
- `L=mean(BCEWithLogits(2*z, (y+1)/2))`；
- 部署动作仍为 `axis_scale*tanh(z)`，原动作 MSE 继续作为报告指标；
- 该 loss 对 z 的梯度为 `(tanh(z)−y)/元素数`，不会再额外乘饱和 tanh 的导数；对内部网络同样传播。

这是改变优化目标，不是无损后端替换。其每个有限内区间目标的最优动作仍为教师动作；目标在±1端点时最优 logit仍可无界，故仍需控制更新尺度/监测饱和，但方向反转时梯度不会被 tanh MSE 锁死。第 160 窗以保存数组计算，新 loss 的 vx logit 梯度约 +0.17293/+0.17337（旧 float64 MSE约6e−9，实际 float32保存为0），方向要求降低前进，与负教师一致。

固定 feature 与参数的小型 GPU 检查应覆盖：饱和 z≈±10 且目标相反时梯度有限、非零、符号正确；一次受控更新降低固定样本 logit loss/方向误差；loss不使用目标几何旁路；部署动作在修复前参数下保持相同。

特征缩放是另一个有直接尺度依据的候选，但不应未区分效应就同时改神经动力学。若加入固定训练集尺度或 RMS/LayerNorm，需要说明是否保留群体幅度信息、参数/优化器如何迁移，不能装作原模型无损续训。为当前饱和存档仅缩小输入或重置读出会改变前向行为，须独立登记。不要直接删弱边、钳制神经电位或改图来解决读出尺度。

### B. theta 原因实验：前向完全相同，隔离反向时间路径

建议固定 **第 159 窗末档**与**第 160 窗两帧原训练输入**，保留所有参数、完整神经/感觉初态、1000步前向和 DN 累加顺序，不执行任何 optimizer。这里选择最终邻窗可直接对应新问题和已保存末窗；既有第25/26窗诊断候选仍可作历史方案，不需要挑选更有利窗口。

1. 原完整 1000 步反向作为基线；记录每 50 步边界的 v/g/各延迟 pending 梯度的稳定范数、最大绝对值和有限性，不保存全部大向量。
2. 同参数/初态/输入，只在帧间断开神经状态的反向连接，数值状态和感觉相位不改；只取第二帧动作损失，以隔离前50ms额外信用路径。断开前后动作、DN特征、终态应相同，比较 theta梯度范数/方向/分组贡献。
3. 如需将递归机制与某个临界回路区分，后续可登记“每50步截断神经状态伴随”的配对支路；保持每步DN到readout的局部梯度，不改变前向。该支路改变学习算法，不能称为原1000步梯度的正确替代；不应未看首个配对结果就批量扫参。

注意若第1支采用两帧总loss而第2支只取第二帧，比较不能隔离时间路径；两支必须用相同第二帧loss。原总loss可另记录，只能作保存证据对照。

若确认逐时刻伴随持续放大，可选择有明确新身份的代理梯度幅度阻尼或截断信用时域；两者都会改变训练算法，必须报告保留了完整前向连接组，不等于完整生物学习机制。单纯移到 GPU、增大学习率或增大裁剪阈值不能解释或根治该问题。

### C. 全 GPU 训练边界

当前代码仍有 CPU `SpatialDrive`（float64相位、每步稠密CPU输入）和 `CPUAdamBridge`（`mps_optimizer.py:16–80`），所以不能称为全GPU训练。新版本应把可训练参数、裁剪稳定范数、Adam一二阶矩/更新都留在 MPS；数据读取、封存和独立只读验算可在CPU。已有 phase 使用float64而MPS不支持直接float64，需要独立决定感觉事件是CPU预计算后批量上传（数据预处理），还是新GPU相位表示并登记改变。不得静默CPU fallback或声称逐位保持原CPU Adam。
