# GPU稳定性修复实施计划

对应[gpu-recovery.md](gpu-recovery.md)。A诊断、B/C集成与初始实际门槛均已独立验收；已按[gpu-recovery-integration.md](gpu-recovery-integration.md)完成新的160窗训练预算与独立实际验收，见[运行报告](gpu-recovery-run-20261019.md)。以下保留实施顺序与范围，不再追加本轮训练或检查。

## A实施

1. 静态/保存证据审计由独立只读子任务完成，业务数值实现由一个实施者串行负责。
2. 在learning职责中新增一个完整图训练梯度诊断入口及必要纯helper（包含动作读出/损失，不能放入仅观察神经信号的diagnostics）；复用已有MPSPolicy、MPSLIF、存档严格读取、资源监督和共享锁。禁止改动已封存42份源码。只允许新目录写入，不覆盖旧证据。
3. 父进程登记第159窗来源、原第160窗输入/输出证据、诊断参数、来源SHA和资源；worker实际恢复完整状态。基线分支先运行，再按500/250/100步切断递归梯度的分支逐一恢复同一初态。全部前向值、时钟与DN累加保持；所有分支不调用optimizer。
4. 保存梯度数组、分支动作/特征/完整末态摘要、每50步边界伴随量级、计时/资源、源图前后摘要。数值fixture验证detach只影响反向、跨块重算纯净和logit损失在饱和处仍有正确梯度；不重复已有MPS核检查。
5. 原基线与已保存第160窗采用同设备同源，应先比较bitwise；若存在差异必须披露并停止正式原因判断，不临时放宽门槛。分支对同次基线前向也要求bitwise。独立验收者审查软件后才启动受监督完整图诊断；实际诊断结果再独立复核保存证据。

## B/C修复决定

已冻结并实现：保持既有动作tanh限幅与参数形状，采用有稳定纠错梯度的logit目标；根据配对证据将递归反向范围固定为100步，前向完整图始终保留。GPU感觉/裁剪/Adam采用新的数值身份和严格状态存档。旧160窗参数逐位继承，Adam因梯度目标改变显式清零；详细依据与实际证据见集成规格和原因报告。

训练先小批、跨进程恢复及修复门槛；通过后再有界完成最多一个新增160窗epoch。主Agent协调状态与提交，新独立Agent验收，不因为预算剩余就继续扩展实验。
