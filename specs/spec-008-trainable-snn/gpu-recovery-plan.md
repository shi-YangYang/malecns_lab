# GPU稳定性修复实施计划

对应[gpu-recovery.md](gpu-recovery.md)。当前只A具备实施条件；B/C在诊断后登记，不提前启动训练。

## A实施

1. 静态/保存证据审计由独立只读子任务完成，业务数值实现由一个实施者串行负责。
2. 在现有diagnostics职责中新增一个完整图梯度诊断入口及必要纯helper；复用已有MPSPolicy、MPSLIF、存档严格读取、资源监督和共享锁。禁止改动已封存42份源码。只允许新目录写入，不覆盖旧证据。
3. 父进程登记第159窗来源、原第160窗输入/输出证据、诊断参数、来源SHA和资源；worker实际恢复完整状态。基线分支先运行，再按500/250/100步切断递归梯度的分支逐一恢复同一初态。全部前向值、时钟与DN累加保持；所有分支不调用optimizer。
4. 保存梯度数组、分支动作/特征/完整末态摘要、每50步边界伴随量级、计时/资源、源图前后摘要。数值fixture验证detach只影响反向、跨块重算纯净和logit损失在饱和处仍有正确梯度；不重复已有MPS核检查。
5. 原基线与已保存第160窗采用同设备同源，应先比较bitwise；若存在差异必须披露并停止正式原因判断，不临时放宽门槛。分支对同次基线前向也要求bitwise。独立验收者审查软件后才启动受监督完整图诊断；实际诊断结果再独立复核保存证据。

## B/C待诊断的决定

候选最小修复：保持既有动作tanh限幅与参数形状，采用有稳定纠错梯度的logit目标；根据配对证据选择明确的递归反向范围或其他已测的稳定化，前向完整图始终保留。GPU感觉/裁剪/Adam需要新的数值身份和严格状态存档。修改损失或优化规则时必须说明旧Adam继承/重置依据，不能隐式丢弃旧训练参数。

训练先小批、跨进程恢复及修复门槛；通过后再有界完成最多一个新增160窗epoch。主Agent协调状态与提交，新独立Agent验收，不因为预算剩余就继续扩展实验。

## 验证范围

神经反向/优化/持久化属于S3；只执行本次新增和受影响的定向数值检查与一次登记完整图诊断。诊断不产生训练成果。文档S0只查差异，原CPU/MPS核测试和已验收98窗不重跑。既有未跟踪SciPy审计文档保留。
