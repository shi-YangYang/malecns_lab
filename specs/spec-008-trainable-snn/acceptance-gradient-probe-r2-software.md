## Spec Coverage

- **历史来源保持**：`load_r1` 固定五个历史证据文件 SHA，要求 r1 原 schema、失败状态及注册身份有效；四份诊断源码逐一比对原 Git 提交 `a0dcb3283d371339abf344278ab41c81b1da4100`，42 份旧训练源码仍要求匹配。r2 使用新四源和新协议身份，固定 159→160 锚必须与 r1 相同，未将 r2 代码伪称 r1 原代码。
- **五支执行与生产调用**：`BRANCHES` 固定两支无 hook 完整 1000 步，随后 500/250/100 三支。`observed=False` 不创建 `BoundaryObserver`，明确调用 `policy.forward_tensor`；非完整范围不能走此模式。每支重新恢复同一完整父档，无优化器更新；原 50 步 checkpoint 与短支 detach 实现未改。
- **目标与前向保持**：各支使用相同两帧动作 MSE 加 gain 正则、相同完整 1000 步前向。短支仅截断递归状态信用，DN 运行和仍参与梯度。动作、全部 DN 特征、读出权重/偏置梯度、神经/感觉末态及状态摘要继续要求精确一致。
- **theta 比较分层**：完整范围同时对旧 160、绑定 r1 和同次参考进行比较。`rtol=1e-5, atol=1e-7` 与既有 `tests/test_mps_continuation.py` 的跨路径原始梯度检查一致，同时要求 float32 形状匹配、全有限、零支持和非零符号不变。exact、差异数、绝对/相对差、ULP 和相对 L2 独立保存，不把数值通过称为逐位相同。短支保留统计但不要求 theta 接近原完整范围；全部保存值仍必须有限。
- **分类边界**：只有全部强制比较通过才分类。先判断两次无 hook 是否不同，其次与 r1 是否不同，再判断旧 160；分类明确不证明具体硬件归约是原因，不重标 r1。失败先保存分支证据，再停止后续分支。
- **资源与复核**：共享锁、父 PID 与单次 worker claim、6 GiB 申请、额外 1 GiB 预留、600 秒及 0.1 秒监督不变。输出必须新目录；完整恢复、固定输入、五支库存/SHA、比较结果、观察边界、计数摘要及资源记录由父进程复核。历史感觉 float64 仅用于诊断重放，不称为后续全 GPU 训练。
