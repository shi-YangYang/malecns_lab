# Acceptance — P3c2 连续训练 runner 协议

## Result

**PASS**（协议可实施性）。本验收者未参与协议编写、P3c1 实施或当前 runner 实现，独立审查了包含一般步 Adam 条款的 [P3c2 Review 协议](p3c-training-runner.md)。训练范围、状态延续、来源与封存链、数值复核和首次实际门槛已具体且相互一致，可以由协调者标记 Ready 后交给实施者。

本结论只针对协议。runner 尚未实施，没有生产跨进程续跑、多窗口训练、冻结脑训练或闭环行为结果；不关闭 Spec 008 的 AC3–AC6。

## Spec Coverage

- **研究范围与原目标一致。** joint 训练完整图内部 theta 及读出，frozen_brain 独立从相同初值训练同容量读出，保留完整逐帧神经动态。四个 train 场景、固定次序、每场景 80 帧、两帧窗口、一个 epoch 共 160 窗，在输出前冻结；不混入 val/test、不挑选最低训练损失档、不以急性恢复代替独立冻结脑。该阶段明确是固定教师轨迹的离线模仿，后续神经闭环、未见场景、拓扑和部署仍待独立证据。
- **完整图与模型契约保持。** 延续 r2 的完整参考图、固定背景、感觉编码、全部 DN、50 ms 帧窗和 60 ms 空白预处理；脑核心、策略、教师数据和既有参数/训练存档均不为本批改动。保留原始图与已验收 r2 阴性证据，不用缩图、缩窗、改代理梯度或降学习率自动重试。
- **P3c1 接口与状态边界相容。** 现有 `make_training_optimizer`、保存/恢复完整训练存档和生产加载接口支持所需 joint/frozen 模式。每窗先更新、detach 全部活动状态、清梯度后保存；窗间保留神经电位、突触状态、全部延迟槽和感觉相位，只有新场景重置。场景末存档保留本场景末状态与游标，下一窗执行一次新场景预处理；跨场景保留参数和 Adam。协议明确现有零步存档限制，不伪造优化步数来处理首窗无效输入。
- **run、segment 与预算边界清晰。** run 固定模型、数据、源码、环境、种子与训练范围；segment 独立登记起点、父存档、窗口数及当前资源，不把可用内存变化混入模型身份。每段 1–4 个完整窗口、1 GiB 额外预留、6 GiB 申请上限、600 秒和 0.1 秒采样；父进程不导入 Torch，工作区 OS 锁限制入口并发，Noria/Docker 保持。段号与训练窗口号分离，估计耗时没有写成实测保证。
- **封存顺序没有循环摘要依赖。** evidence → event → prefix → checkpoint → window 形成单向链。event 只含父存档，不引用尚未生成的本窗存档 ID；prefix 绑定事件位置和字节摘要，checkpoint 绑定 prefix，window 最后绑定全部文件及 checkpoint ID。完成标志是最后的 window manifest，不能仅凭 checkpoint 目录或 worker 计数增加训练进度。
- **真实来源与恢复链需要独立核对。** 协议要求真实 dataset 清单/帧数/输入序列、实际 prefix 文件及事件、根训练 manifest、nested 参数、训练状态和矩与登记交叉核对；不是仅验证摘要字符串格式。路径由段号/窗口号生成，拒绝越界、重复/跳号和分叉。恢复必须沿唯一连续的已验证链；worker 在任何前向前保存实际恢复的参数、Adam 和完整状态摘要，与父存档逐值/摘要核对，不额外预处理或重复前一更新。
- **失败与可恢复进展分别表述。** 资源/进程失败保持 failed，只能另外报告证据与资源条件成立的 recoverable_prefix；未封存尾部保留但不计数。损坏已封存窗口、数值异常和链不一致拒绝恢复，不能回退到更旧边界掩盖错误，也没有同次自动重试。后续显式续段与首两窗门槛由协调者推进，不借分段工具默认启动全 epoch。
- **一般步 Adam 可被证据复核。** 明确从每窗实际旧矩开始，保存实际新矩与参数、稳定组裁剪和真实 float32 系数；固定 lerp 的抵消处理、二阶矩乘法次序、bias correction、下溢语义和原容差。先校验新矩再复算参数，避免跨窗累积近似矩或只检查参数差。安装的 Torch 非 foreach/非 fused 路径静态源码与所述 lerp、mul/addcmul、sqrt/div/add、addcdiv 次序一致。协议对 float64 乘加模拟仅作当前环境及有限算术证据支持的约束，没有声称普遍 fmaf 等价；后续定向测试必须包含抵消例和多步矩传递。
- **首次实际门槛可观察且不重复旧实验。** joint 窗口 1、2 强制两个 worker；首窗与旧 r2 相同输入的 baseline/梯度/初值/更新核对，第二窗验证实际恢复并推进到 frame 4。首两窗是新训练 run 的有效前缀，不是重跑 r2 五分支，也不再运行一条重复的完整图连续前缀来证明恢复。独立实际验收通过后才推进其余窗口，损失不要求必降。

## Regression Risks

- r2 有限但巨大的内部梯度和本步内部收益阴性仍有效；连续训练可能数值失败，协议的裁剪与逐窗复核不保证学会控制。
- 第一个完整 epoch 的耗时、存档/恢复成本、跨进程一致性和长轨迹稳定性尚未实测。采样资源监督不是硬隔离，4 窗约 400 秒仅为预估。
- 父进程需新增不导入 Torch 的完整证据复核，不能直接导入现有 `training_checkpoint` 替代；应逐窗释放状态，避免校验时累积保存所有完整状态。
- manifest-last 拒绝未封存尾部，不构成文件系统事务或掉电恢复保证；恢复链错误必须明确失败，不能由一次进程 exit 0 掩盖。
