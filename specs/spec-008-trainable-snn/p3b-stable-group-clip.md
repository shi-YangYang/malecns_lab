# P3b r2 — 稳定范数与分参数组裁剪候选

## 原因与范围

r1在完整图上完成两帧连续100ms前向/反向。全部梯度元素有限，但theta的float64 L2为7.7855612135e31，现行float32范数归约溢出，更新尚未发生。内存门槛未触发。此处区分两个问题：有限大值的范数算术溢出，以及内部/读出梯度约4.97e29倍的尺度失衡。

只读Agent对原始`gradients_before_clip.npz`和初始参数作NumPy算术分析，没有执行Torch优化器或神经网络：若仅修全局范数，裁剪系数约1.2844289224e−32，读出权重最大理论Adam步约2.98e−27，不足以改变任何现有float32权重；零初始化bias虽能表示约1e−28的变化，但动作量级远小于原容差。该预测不是实际参数更新证据，微小theta/gain变化数可能受内核舍入影响。

候选分别裁剪theta、weight+bias后，读出组系数约0.00638469355，预计读出权重可产生可表示变化。这仅为设计依据，**改变了优化规则**，不能称为原统一裁剪的等价bug修复。它不解释或解决内部梯度为何巨大，也不预判动作损失改善。

## 新的数值契约

1. 裁剪前逐元素检查三个原始梯度的有限性；NaN/Inf立即失败并保留原始梯度。不能关闭非有限保护。
2. 使用float64归约记录全参数L2及两个组的L2；本候选的参数与计算本体仍为CPU float32。仅范数/统计升精度，不将完整模型改为float64。
3. 组固定为`[brain.theta]`和`[readout.weight, readout.bias]`，每组最大L2均1.0，分别计算`min(1, 1/(group_norm+1e-6))`。记录float64系数，将其转换为float32后乘入原float32梯度，同时保存实际乘法系数和三个完整裁剪后梯度。总参数范数不再要求≤1，两个组均满足上限，合并上限为sqrt(2)；不得仍称为旧的统一裁剪。父复核用float64统计裁剪后范数，允许上限的1e−6浮点误差，不在实际运行后调整。
4. 恰好一次Adam，完整保存实际更新与三个命名参数各自的step、exp_avg、exp_avg_sq，优化器参数组仍只有两个；这些仅用于本次优化数值证据，不称为续训存档。矩数组为与参数同形状的float32，step为float32标量且严格等于1，字段/shape/dtype/有限性均检查。父进程从初始零矩状态、实际裁剪后梯度独立复算矩/step/参数更新，按实际float32操作和下溢语义验证矩，不能只用float64理想首步公式。矩比较固定rtol1e−6、atol为float32最小正次正规数；实现阶段的定向数值检查须确认该契约。
5. 记录两个组原始/裁剪后范数、非零量和更新量；theta巨大梯度本身不自动当作学习成功。原始正则梯度仍须零，rho固定不变。
6. 新登记绑定r1的registration/protocol ID及参与比较文件的字节SHA，按旧登记/终态摘要核对其来源；不能因当前源码版本不同改写旧身份。同一固定输入的baseline动作、全部DN特征、theta/读出初始化和原始梯度与r1已保存值比较，分别报告exact/allclose/maxdiff；这检验本候选只在反向完成后的优化环节改变行为，不额外重跑r1。容差沿用rtol1e−6/atol1e−7，初始参数要求精确相同。超容差使本次协议无效，保留诊断后再分析，不能凭事后解释放行或放宽阈值。
