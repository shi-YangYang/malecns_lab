## Validation

- Risk Level：S2；相关证据读写、监督和 checkpoint 交互返工，未改变数值核心或固定研究协议。
- 阅读项目规则、验收流程、当前交接、Spec 008 Plan、Decision 009、P1/P1a/返工规格、原 FAIL 与两轮实施报告。
- 审查全部 `probe.py`、`probe_evidence.py`、`resource_guard.py`、`checkpoint.py`、两份定向测试文件、对应文档差异，以及核心/图身份的实际生产接口。未将其他并行映射改动计入本批。
- 对照真实 worker 的产物构造：完整图 body ID 经生产 loader 规范为升序 int64；基线、更新和两种恢复响应来自 CPU float32 核心；内部 theta/gradient/gain 均保存原 float32 数组；登记字符串通过 `np.savez` 存为标量 Unicode，与验证器字段、精度和维度要求一致。
- 对照真实 checkpoint 保存：可选 `run_identity` 在计算 `checkpoint_id` 前加入元数据，完整模型身份、theta 精度/形状及参数文件摘要一并纳入。与轻量验证器使用相同 JSON 排序/分隔编码和 SHA256；有限元数据范围内新增 `allow_nan=False` 不改变摘要。恢复路径仍先核对模型/图/分组/输入/精度身份再写参数。
- 对照数值和阶段统计：真实 worker 与验证器使用同一 float64 损失归约及梯度范数、同一 float32 参数/响应差值；固定 Adam 默认首步对应所复核的更新式。成功路径的阶段转换恰好覆盖登记的13个阶段，`finished` 关闭最后阶段但不会新增被拒绝的阶段项。实际原图摘要复查与构造时按相同数组顺序、little-endian int64 字节计算。
- 接受实施者已有 **30 passed / 12 deselected** 的针对性检查证据，逐项阅读其完整软件产物、缺失/矛盾/错身份/错精度/错误更新拒绝及裸状态字符串回归。未发现需要新增运行才能解决的具体覆盖缺口，因此没有重复测试、执行全项目检查或启动数值仿真。
- 只读核对首轮登记/结果及文档差异；没有修改业务代码、旧资产、原 FAIL，没有提交，没有操作硬件或重新登记全图运行。

## Regression Risks

- 尚无真实完整图 worker 完整执行产生的数值产物。静态 writer/validator 对照与软件夹具不能替代实际规模的梯度、耗时、内存和恢复证据；这些仍是 P1 的验收内容。
- 本地文件的一致性验证可以识别缺失、损坏、跨运行混用和内部矛盾，不能证明人为构造的全套一致文件真实发生过；图来源依赖登记代码中的生产完整参考图加载器。
- 验证要求当前实现摘要与登记相同；修改相关实现后必须新登记，不能直接把旧登记当作当前版本运行证据。首轮失败资产保持原版本历史身份。

## Required Rework

无。P1a 工具可以作为独立软件步骤提交；等待用户明确通知内存释放完成后，由协调者按既定预算在新目录登记实际完整图探针。不得将本 PASS 扩展为网络已学会控制无人机。
