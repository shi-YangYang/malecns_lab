## Issues

### R1 — 最终训练准入未要求父进程已封存终态（P1）

位置：`src/cnsbridge/learning/evaluation_contract.py:74`–99，尤其 79–86；所调用既有 `training_evidence.scan_run` 的 result 分支只在文件存在时检查，且没有将缺少父终态作为错误。

可确定的反例：一个训练段已经写完并封存第160窗，资源采样覆盖该封存点，但父进程在写 `result.json` 前退出。`scan_run` 会返回160窗及最终 checkpoint；`final_training_source` 只检查该计数/游标再读存档，随后登记为最终训练来源。将完整训练副本的末段 `result.json` 移除也走同一路径。其 source 身份只绑定 run 与最终存档文件，不绑定该缺失的最终父终态；因此当前检查无法区分“父已复核的最终训练”和“仍未决的已封存前缀”。

这不等于需要拒绝所有历史资源失败：历史资源失败但父已明确复核并封存的有效前缀可以按既有协议续训，最终通过完整链准入。缺父 result 的未决段、父报告 invalid evidence、数值/协议失败则不能借恢复用 scanner 的宽松返回值进入正式评估。数值失败已有部分防护，但不补足缺失父终态。

要求在**新增评估准入层**严格核对每段父终态、原始 supervisor/worker 与 terminal artifact 清单和 SHA，拒绝未决或证据失败段；明确最终来源的完成状态并将终态来源绑定进登记。不得修改当前已绑定的29个训练源码来修复本批。补充定向准入检查：完整合规最终链、缺末段父 result、父证据失败，以及允许的已验证资源失败前缀后继续完成，分别得到正确结果。

### R2 — 资源失败的终局被计作已完成场景并开放后续矩阵（P1）

位置：`src/cnsbridge/learning/evaluation_evidence.py:225`–238、261–275、285–305、324–333。

可确定的反例：最后一个块已经封存第80帧，随后 supervisor 因墙钟/RSS/系统预留失败；或者块内发生真实物理终止、保存完成后出现 IO/资源失败。父仍保留 failed 原值及合规 sealed prefix。`scan_episode` 重放该前缀得到 `terminal=True`，`episode_report` 首先判断 terminal，返回 `duration_complete`/`physical_failure`，完全绕过后面的失败状态判断。`scan_suite`、`comparisons` 和 `check_order` 又仅依赖 terminal，因此该失败段被计入 val_complete/完整均值，允许进入后续场景乃至 test。

协议明确“资源/数值/证据失败不算完成场景”，且要求缺失、资源失败和物理失败分开。保存的物理终局和合法前缀应保留，但不能因此把失败段自动升级为正式完成；完整80帧时还可能连带展示 `metrics.success=True`，而最终参数/图保持等 worker 完成检查只在 completed 段执行。

要求区分**环境已终止**与**正式场景证据已完成**，由经过父终态验证的完成状态驱动冻结顺序、val/test 门槛、完整均值及配对比较。失败段的环境终局、原始 supervisor、有效前缀和局部指标保留并明确标注；不得重复前向终局或静默重试来凑完整场景。若需要另设显式终态复核恢复，应先由协调者冻结其规则，不能从当前 failed 自动放行。补充“正常终局完成 / 终局后资源或 IO 失败 / 非终局失败前缀显式恢复 / 真实物理失败且完成封存”的交叉检查，验证失败不会解锁下一场景或 test。
