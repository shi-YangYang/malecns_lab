# 完整图反向内核与线程成本实测 — 2026-10-19

## 结论与边界

完整伴随矩阵的本次 CPU 实测中，SciPy 路径约15.7–15.8ms/次，相比当前 Torch 4线程约71.9–72.2ms/次，核级吞吐约4.56–4.59倍。Torch增加到8或10线程约56.9–58.7ms/次，耗时减少约19–21%。SciPy及8/10线程均满足预先固定的核级候选条件；1/2线程比4线程更慢，全部保留。

180次调用和270组逐输出比较（包含预热）数值全部精确相同，max-abs和RMS差均为0；完整图、输入和缓存未改变。这些是固定合成数值向量上的结果，尚未测实际训练上游梯度、自定义autograd或完整更新窗；**不能把4.6倍称为整个训练的加速**，旧训练实现和参数未被迁移。新的[独立实际验收PASS](acceptance-backward-kernel-run-r1.md)已全文读取处理，无返工项；原始输出、摘要和计时另行复算一致。

## 为什么检查这里

用户观察活动监视器CPU/GPU利用率偏低。本轮joint第17段反向阶段的3秒现场psutil采样为worker约266.4% CPU，即约2.7个核心；本机10核，当前登记Torch4线程/interop1，CPUfloat32，代码未使用GPU。采样是现场观察，不在只有wall/RSS/available的训练CSV中，不把它冒充全程CPU遥测。

该段四个两帧窗的前向20.59–23.08s，反向/裁剪84.97–87.35s，见[原始续段记录](p3c-continuation-20261019.md)。后者包含损失构造、反向、梯度复制和裁剪，不等同孤立SpMV。每两帧共1000个神经时间步，状态依次推进。当前前向已经是SciPy共享CSR，反向使用一次预建的Torch伴随CSR；不存在每步重复转置，应避免错误归因。

另外一次3秒系统`vm_stat`差分见80页swapin、0页swapout（页大小16384 bytes），并有压缩/解压缩活动。它是系统级短采样，不能据既有swap占用或RSS降低断言训练主要受交换限制，也不能排除整个运行中其他时段的内存影响。Noria/Docker未操作。

## 数值和共享缓存证据

三种输入均为166700个float32：zero全零；sparse使用seed1901无放回选择1667项为1；同一生成器继续产生uniform(-1,1) dense，选中索引与输入文件保存并核对前后摘要。它们不是实际训练梯度采样。

5线程×3输入×6输出轮×2实现共180次；逐轮SciPy/Torch、Torch/Torch4、SciPy/Torch4共270组比较。全部有限、shape/dtype正确、精确相同，固定rtol/atol均1e−5未放宽。

共享CSR为166700×166700、25582938项，data float32，indices/indptr int64；Torch/NumPy/SciPy地址相同、顺序和数值相同、视图只读且前后指针/摘要不变。共享视图构造约0.000038708s，计时包含每次输入NumPy视图和输出Torch包装，不包含构造、结果复制或写盘。shared-adjoint整个相位约0.1889s还包含证据检查/摘要等，不能误称为纯构造时间。结束恢复Torch4线程，interop仍1。

地址和图前后摘要来自绑定worker的运行记录；独立验收直接复算保存的输入/输出、文件摘要与计时，但未重建完整矩阵或再次检查已退出进程的活指针。这是一次完整图运行加独立证据复核，不是两次独立全图运行。
