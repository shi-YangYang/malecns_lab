## Spec Coverage

- **固定研究来源与模式**：`training_contract` 绑定完整参考图文件/provenance、真实封存数据身份及清单、四个 80 帧 train 场景和 160 窗预算、运行时/线程、所有新增模块和实际复用的既有源码。r2 九个固定字节锚点进一步关联其原终态/worker 文件清单及模型来源。生产 worker 独立构造或恢复 full_reference，并核对实际策略和原始图计数摘要；没有小图或缓存特征生产回退。
- **两帧训练与完整状态**：`compute_window` 连续传播两帧后计算同帧有效标签的归一化动作损失及内部 gain 正则，真实更新后 detach 全部状态并清梯度；窗口内没有 detach/reset。`execute_windows` 只在每场景第一帧调用一次预处理，跨场景保留参数和 Adam。冻结脑模式只训练读出而保留逐帧脑计算，独立初值来源与 joint 相同。无效窗跳过整个更新但推进状态；第一次全无效无法保存零步存档，明确失败。
- **一般步数值证据**：保存更新前后全部参数、gain/rho、实际命名 Adam 状态、原始和实际裁剪梯度；首步真实无 Adam state 有显式标记。父复核从绑定的实际旧矩开始，按协议的 float32 delta / float64 乘加 / float32 舍入及二阶矩顺序检查，再以已经检查的实际新矩复算参数，保持原容差。稳定分组范数在 float64 中计算，实际系数为 float32；冻结参数、跳步、实际 step、下溢、有效 gain 范围及动作读出均核对。
- **来源、游标及封存链**：evidence → event → prefix → checkpoint → window 的顺序没有循环依赖。父检查将保存输入与真实数据逐值比较，独立推导下一场景/帧/窗口/优化步，重建固定相对路径的规范事件前缀。完整训练存档的外部 run 身份、nested 参数、矩、全部活动状态与事件和证据交叉核对；末尾 window manifest 缺失不计进度。逐窗只保留小参数/矩及状态摘要，没有累积保存完整状态数组。
- **实际恢复证据**：下一 worker 先加载已验证父存档，在任何前向或新场景预处理前保存实际参数、Adam、状态摘要和原游标，再逐值/摘要核对父档。同场景开始状态必须等于前窗末状态；场景边界保留前场景末档，后续才重置。不得通过跳到旧档隐藏坏父链、重复/漏窗、错误前缀或损坏封存档。
- **监督及失败边界**：父入口不导入 Torch/训练存档；所有生产模型构造和计算在受监督 worker。每段 1–4 窗，1 GiB 额外预留、6 GiB 申请上限、600 s、0.1 s 采样；工作区 OS 文件锁在父入口持有。资源/进程失败保持 failed，只有已封存且资源采样覆盖的合法前缀可单独列出。数值/协议失败无 recoverable_prefix 且阻止继续原 run。exit 0 还必须满足全部窗口、worker 终态及原始图/终态清单检查，不能自动升级为训练完成。
- **资源时钟保守边界**：登记时钟早于监督 CSV 原点。当前实现使用更严格的 elapsed 下界，必须存在足够晚且预算内的采样；不足时明确拒绝，不扩大预算。该偏移可能导致假阴性，文档及针对性检查如实说明，没有把它说成精确时钟对齐。
- **首次实际门槛与进度**：joint 首窗封存前检查 r2 初值、相同输入、动作/全部 DN 特征、原始梯度和更新；超差保留诊断且不封存。首两个单窗调用及独立实际验收由协调者按协议推进，CLI 不自动跑完整 epoch 或重试。进度从实际封存链汇总帧、有效帧、窗口、更新、轴范围、资源与最后存档；epoch_complete 明确只指固定教师轨迹的离线训练预算完成。
- **范围控制**：原有脑、策略、感觉、数据、参数/训练存档、优化器、P3b 和监督源码未修改。文档将工具能力与真实完整图/学习效果分开。协调者另写的 P3d Draft 不属于本实施验收，也没有因本报告变为 Ready。

## Regression Risks

- 当前固定 CPU float32、相同源码/运行时/线程、封存数据和单 epoch；不支持任意数据替换、跨版本迁移或全无效首窗。
- 资源采样及保守时钟边界可能拒绝临近末采样的有效窗口，manifest-last 不提供文件系统事务或掉电恢复保证；原始失败及尾部保持。
- 160 窗的扫描/存档/重启成本与多窗资源开销尚无生产实测，4 窗约 400 s 仍只是估计。实际超限或数值超差须保留证据，再定具体下一步，不能裁图或调阈值掩盖。
