# M5a 采样封存与联合批次限定返工

日期：2026-10-23。实施者：`roadmap_m5_capture_repair`，独立 FAIL 后的新实施者。范围仅 `m5-capture-acceptance.md` 的 R1/R2，风险 S3（档案终态、受限读取及 IPC），待新的独立验收。未修改 Python、M1/M3 或训练来源，未启动 Electron、仿真、脑或硬件，未 commit；M5b 视频没有加入。

## R1：迟到摘要不能取消超时终态

- `recording.mjs` 在发布新采样 manifest 前先持久化 `seal_pending.json`，绑定身份和 generation；manifest 声明 `pending_marker_v1` 封存规则。
- 2 秒封存等待、I/O 异常或进程退出留下该标记。即使已进入异步 `link` 的旧摘要随后成功落盘，读取端仍优先返回 `incomplete / complete=false / replay=null`，不会把摘要里的 `sealed` 当作最终决定。
- 摘要异步发布全部返回后，实施代码再次检查 generation 和期限；只有在当前 generation、未超时的同一事件循环段内，以一次同步 `unlinkSync` 撤销 pending 标记，并更新内存终态。此处不再引入可被超时回调穿过的异步提交窗口。图片、索引、摘要的写入仍异步；同步范围只有一个本地元数据删除系统调用，没有新增同步图片写入或重试。
- 读取端同时核对摘要与 manifest 的 generation。旧无画面记录保持原来的脑回放；缺少新封存规则的旧画面档案明确标为不完整，仍可单独回放旧脑数据，不追认其联合回放完整性。

## R2：索引绑定实际返回的脑批次

- 构建联合索引时，从同一次受限文件读取中解析并计算批次 SHA256、字节数，保留原始 Number 时间；核对文件名序号与内容序号。未修改 Python 遥测 schema 或 16 MiB 档案额度。
- 打开联合档案时重新读取所引用批次，检查内容 hash/字节数、run/session/神经 execution/checkpoint/input map、序号及原始/归一化时间；重复序号拒绝。批次损坏或同身份下被修改时，控制器将画面档案标为 `invalid`，不提供联合回放索引。
- 实际联合 `readBatch` IPC 增加可选的整数游标索引；主进程用已验证的索引确定该时刻最后一批，拒绝请求未来或不属于当前游标的批次，并对**最终返回的文件字节**再次验证，覆盖打开档案后、取数据前的修改窗口。原来的两参数旧脑回放路径保留，没有新增任意路径/URL/命令权限。
- renderer 联合路径传递游标索引，并在显示前核对返回批次的序号、身份、原始时间、索引时间及“不晚于游标”；不再只信任打开时的静态序号数组。布局、播放操作与既有权限均保持原范围。

## 限制与交回

新封存规则避免可延迟 Promise 导致超时终态反转；最后一次同步元数据删除仍受操作系统文件系统调用延迟影响，2 秒是异步封存等待预算，不是硬实时系统调用保证。该调用只在控制清理已完成后的档案封存路径，不参与停车确认。
