# M4 实际反馈来源关联修复

2026-10-23，Ready，风险 S2。依据 [真实反馈准备度](m3-real-feedback-readiness.md) 的一个可达错配：`SkillExecutor.update_odom/update_mc` 可同步发执行事件，此时 bridge 尚未更新 `raw_latest`，附带原文可能来自上一回调。尚未证明该错配发生于历史实测；不改旧记录。

## 范围与验收

只修改 `experiments/x2_behavior_bridge.py`、`learning/x2_behavior_session.py` 及其最小相关测试。2026-10-23核对正在运行的 readout r1 `registration.json.source_sha256`，这两个文件均不在冻结来源清单；因此可与训练并行做轻量代码实施，但禁止改训练来源、模型、编码、Observation schema、技能执行语义或启动实际资源。该结论收窄并替代准备度报告中对所有后续修改统一等待训练退出的安排。新的实际 M4 run 仍须在训练结束后登记新来源。

1. 每次 odom/MC 回调在调用 executor 前固定原始 message、唯一快照ID及一次实际接收时刻，使同步执行事件能引用触发它的本次输入。保留接受/拒绝结果，不在执行事件发出前假设更新已被接受。若保留其他传感器最近值，明确各自来源，不能标成同一时刻测得。
2. 构造有效 Feedback 时只引用与当前 core 的序号/接收时刻匹配的已接受快照；缺失/不匹配明确失败，不能回退到旧原文。当前拒绝会清空 core，继续保持该行为，不修复一个不存在的“旧有效测量混入”路径。非朝向任务也须能追溯 odom 和 MC 原文。
3. `observation_sent` 归档完整响应或稳定的原始记录引用，绑定 nonce、远端序号、各自时钟和被发送的实际 Feedback。可直接扩展现有追加日志，避免建立重复大文件；不能只依赖会被覆盖的邮箱。原始快照只作证据，不能进入读出或增加教师输入。
4. 在 host 记录中明确区分真正送入脑的 Observation 与仅供门禁刷新的 Observation。实际入脑记录应发生在拒绝反馈投影后，绑定 observation_seq、decision_seq、request_id；计算中止保留“尝试”而非伪造完成。`raw_decision` 仍是完成计算的关联证据。保留既有 `observation` 记录和旧归档读取契约。
5. 不增加后台轮询、传感器订阅频率或动作。保护停止优先、请求边缘消费、相对朝向、真实拒绝投影和控制权判定全部保持。没有真实数据导出器、教师标签、v1数据修改或locked_test读取。

一个定向 CPU 检查覆盖同步 STARTED/UNKNOWN 触发原文、接受/拒绝来源匹配、非转向快照关联与入脑/门禁日志区别。可在已有小测试文件中增加有意义的回归，不启动完整脑/MPS/仿真；不机械复跑已通过的桌面或训练检查。实施报告记录实际变更和检查，新独立审查者只核对本次关联修复，完成后停止。

本修复通过只表明后续记录具有可追溯来源，不等于实际反馈训练、P3/P5任务成功或真机通过。
