# M5 展示与同次画面回放：最小实施范围审查

日期：2026-10-23。状态：**只读准备完成；M5 未实施、未验收**。本报告只新增范围建议，没有改业务代码，也没有运行 Electron、训练、仿真、测试或 build。当前唯一完整脑读出训练由协调者监督，本报告不改变其来源、数据或预算。

## 结论

先沿现有 Electron 实现**同一次桌面运行的仿真视口采样帧、真实脑遥测和任务/执行事件关联回放**，加三类人工操作脚本及明确失败恢复。使用现有 Electron/Node 能力，无新依赖，不改 SDK、MC、脑策略或学习源码。

这能补上“离线脑回放左侧没有画面”的工程缺口，但采样帧不是连续视频，不能据此声称已经完成计划中的完整录像交付。M5 拆成可审查的两个结果：M5a 采样画面与同次记录回放，M5b 连续视频归档（仍待单独选定并实测）。M2 技能资格、M3 合格候选和 M4/P5 的真实互动不能由回放功能替代。

## 已有能力与实际缺口

| 代码位置 | 已有事实 | M5 最小变化 |
|---|---|---|
| `apps/desktop/electron/main.mjs` | 左侧是独立 session 的 `WebContentsView`，只允许本地 6081；隐藏/最小化会隐藏视图；关闭先调用控制器停止并等清理 | 主进程采集该视图，绑定当前 run；把采样结束纳入有界关闭过程 |
| `apps/desktop/electron/controller.mjs` | 主进程创建固定 `desktop-*` 目录，具体任务 IPC；只打开终态且 `resources_stopped=true` 的记录；遥测总量上限 16 MiB | 识别可选画面档案，受限读取帧和回放索引；画面额度与原遥测额度分开 |
| `apps/desktop/src/main.ts` | 记录选择器、上一批/下一批；回放时隐藏实时 noVNC，明确“回放无画面” | 新档案使用主机时间游标，旧档案仍可逐批查看；左侧显示保存的采样帧 |
| `apps/desktop/src/data.ts`、`types.ts` | 校验 run、神经 session、checkpoint、input_map 和批次；32 个选样神经元真实事件 | 增加独立画面/回放类型及身份校验，不改旧遥测 schema |
| `learning/x2_behavior_telemetry.py` | 同一个策略实例输出真实脉冲；`execution_id` 是神经会话，`skill_execution_id` 才是单技能 | 原样引用并保留语义，不把两种 execution ID 混用 |
| `learning/x2_behavior_session.py`、`experiments/x2_behavior_bridge.py` | 已有任务、原始脑决策、实际执行、远端时钟往返证据 | 只从本 run 原始记录生成有界回放索引，不从画面猜成功，不另设动作编排 |

当前回放按神经批次推进。技能执行期间可能没有新脑批次；仅为每批配一张图会漏掉这段运动，不能作为 M5 的完整交互回看方法。

## 可用采集方式与取舍

推荐 `simulation.webContents.capturePage(undefined, { stayHidden: true, stayAwake: false })`，取得 `NativeImage` 后在主进程用 `toJPEG(70)` 保存。Electron 官方将此接口定义为页面快照；`stayHidden`/`stayAwake` 控制隐藏与休眠行为，并不保证定帧率或完整视频。[webContents.capturePage](https://www.electronjs.org/docs/latest/api/web-contents#contentscapturepagerect-opts)、[NativeImage.toJPEG](https://www.electronjs.org/docs/latest/api/native-image#imagetojpegquality)

本地 `apps/desktop/node_modules/electron/electron.d.ts` 的 Electron 45.0.0 类型确实包含这些参数及 JPEG API。这里只做静态核对，尚未实测当前 noVNC 视图能否持续成功截图及采样开销。

采集对象是**noVNC 视口实际呈现的页面**，包括可能出现的断线提示、控件或停滞画面；不是 Sim 的离屏原始帧，也没有每个像素的仿真源时间。页面成功截图不证明 VNC 仍在更新，`simulator_ready` 也不能证明最新像素。首轮实测必须检查档案确实包含当次运动与断线状态。UI 可称“画面回放”或“采样回放”，不能称“60 fps 录像”或“逐物理帧同步”。

连续视频的候选是 Electron `desktopCapturer` 配合媒体流录制，但官方该接口选择屏幕/窗口源，涉及显示媒体权限；macOS 屏幕采集要求用户同意。现有隔离 noVNC 子视图不是文档保证可单独选择的视频源，不能直接假定能录到它，也不能误录其他窗口。此途径会扩大当前权限和身份验证范围，暂不纳入 M5a。[Electron desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer)

本轮也不注入 noVNC 脚本抓 canvas、不新增 FFmpeg、不改为 offscreen 渲染，不用截图拼接文件冒称原始连续录像。M5b 在 M5a 实际开销与需要明确后再登记；没有验证的路径不写成已可用。

## 三类展示流程

脚本是操作人员的任务输入与观察说明，不是运行时“任务 → MC 动作”程序。保留现有五个任务按钮、普通结束和独立紧急停止。15–30 秒只记录为体验目标，每轮报告实际时间。

| 流程 | 操作人员提交的意图 | 应记录的观察；不由脚本补动作 |
|---|---|---|
| 正常互动 | 准备完成后提交 GREET；完成后提交 END_INTERACTION | 脑原始选择、实际挥手开始/完成/待命；普通结束是否由脑完成 |
| 方向致意 | 每轮提交 FACE_LEFT 或 FACE_RIGHT；完成后普通结束 | 当次固定目标、真实朝向误差、脑选择转向/等待/挥手的顺序与实际停止反馈；左右分别记录 |
| 连续任务切换 | 预登记一次 GREET → FACE_LEFT/RIGHT 或 SHOW_FORWARD → END_INTERACTION 的请求变化时点 | 请求在计算中/执行中变更、旧推理被拒绝或完成、后续新请求真实进入脑；不得用定时器替脑选择下一技能 |

“完成后”来自原始事件和既定任务评分，不来自截图看起来像动作结束；不把 `state=completed` 或程序预算结束等同于任务成功。连续切换的每次新 request_id 必须保留；不把一次请求内部的动作序列误记为多次用户请求。

当前挥手能力关闭，左右转向尚未全部通过，以上完整流程**不能作为已可演示能力**。M5a 可以先完成档案工程和失败回放；正式演示脚本只有依赖资格通过才执行。未通过的模型/技能不得被操作员补点动作掩盖。

## 建议文件边界与接口

由同一实施者负责下列耦合桌面变更，避免采集、封存和读取边界分散。协调者维护实际运行登记与展示脚本，新的验收者审阅。

- 新增一个有实质职责的 `apps/desktop/electron/recording.mjs`：有界采样循环、不可覆盖的图片写入、清单/汇总、受限档案解析。注入 capture/clock 便于纯 CPU 定向检查；不建立空转发层。
- `main.mjs`：仅主进程持有 `simulation.webContents` 并调用采样器；接入可见性、加载失败、renderer 退出和关闭。采样器不能持有任务发送或 MC 能力。
- `controller.mjs`、`boundaries.mjs`：验证本次输出根目录及登记身份，列出和读取封存后的画面索引；图片读取有独立上限、符号链接检查、序号白名单和完整性校验。
- `preload.cjs`、`types.ts`：至多新增具体的 `readRecordedFrame(recordId, frameSequence)` 和有界回放索引读取；返回已验证 JPEG 字节与元数据，不暴露路径、URL、`webContents`、任意 capture 或 shell。
- `src/main.ts`、`data.ts`、必要的 `style.css`：已有左侧容器放档案图片；现有面板按钮承担上一步/下一步，必要时加小型播放/暂停按钮。**不恢复底部播放条、大标题或被用户删除的历史小字**。回放隐藏实时视图，禁止任务提交；旧记录缺画面时继续明确无画面。
- `apps/desktop/README.md` 与 Spec024 独立实施/验收报告：写真实启动、停机、恢复、采样性质和已验证限制。当前 README 旧“两轮纵向”段落与新候选入口并存，实施说明应使现行操作清楚，但不扩展到重写历史科研文档。

不要修改 M1/M3、神经采样器、训练来源或官方仿真模块。需要的身份和事件优先从本次 `behavior_registration.json`、`brain_ready.json`、`telemetry/manifest.json`、`task_requests.jsonl`、`behavior_events.jsonl`、`bridge_events.jsonl` 读取。不要为方便显示而更改来源快照、原始时间戳或既有 schema。

## 档案、身份与有限预算建议

以下值是**待实施冻结的建议**，不是现有程序参数或测得性能：

```text
desktop-<固定运行ID>/
  simulation_capture/
    manifest.json
    frames/000001.jpg
    frame_index.jsonl
    summary.json
    replay_index.json
```

- 新 schema 使用独立的 `malecns_lab.x2_simulation_capture.*.v1`；manifest 标明 `media_kind=sampled_frames`、`source=novnc_webcontents_snapshot`、原生视口采集。绑定 record_id/run_id/session_id、神经 execution_id、checkpoint_id、policy_id、input_map_id、backend=sim、官方资源与桌面采集源码 hash。必须先交叉核对本次登记、brain_ready 与遥测 manifest，缺项/不符则不创建伪关联。
- 采样目标 2 Hz，单次只允许一个 capture 在途，不堆队列、不追赶漏拍。保留实际开始/结束时刻和 skipped/error 计数；视口隐藏、最小化、加载失败、运行结束立即停止或暂停采样并记录区间。不启用隐藏窗口持续渲染或防休眠。
- 拟定上限：随已有 GPU VM 最长 240 秒、最多 480 张、单图 512 KiB、画面档案总 256 MiB，索引总 4 MiB；像素不超过 1280×800，按比例缩小且不放大。所有值在清单冻结，尺寸/字节超限不偷偷降低质量或无限写入。开始时保留至少 512 MiB 可用磁盘；这是画面预算，不取代既有 1 GiB 系统内存预留。
- 每帧保存实际像素尺寸、SHA-256、字节数、capture 起止主机单调时间、当前页面/视图状态；参考的 request/decision/skill ID 只取本次已知事件，未知为 null。该关联是“当时已知上下文”，不能把后续执行 ID 回填成截图时已执行。
- 写入采用新文件和临时文件原子落盘，完成后才纳入索引；不得覆盖旧帧/run。录制尚未完成或进程崩溃的档案保留并标 incomplete，不补造 summary，不从其他 run 借图。
- 原遥测 16 MiB 限额保持原义；图片不塞入遥测目录或伪装 JSON 扩容。打开回放只读取索引与单张图片，不预载整个图集。

## 时钟与回放语义

1. **主游标用主机单调时间。** 神经 `step × dt_ms` 是模拟神经时间，不能按它压缩几秒的推理/运动。Node 采样时记录 `process.hrtime.bigint()` 起止值；新档案整数纳秒用十进制字符串保存，避免 JavaScript Number 精度丢失。既有 Python 纳秒字段原样保存并报告其可解析精度，不改老数据。
2. 当前桌面已经按 macOS 同机单调时钟比较 Node/Python 时间。新采集须在本机实际验证可比较性并把时钟域/运行身份登记；不能泛化为跨主机天然同步。不满足时只能分别查看，禁止给出貌似精确的联合游标。
3. 帧是本机 VNC 接收画面的采样，记录 capture 起止区间；**无仿真像素源时间，不声称物理帧级对齐**。MC/odom 的 Linux 单调时刻不能直接减主机时间；展示其主机接收时间及现有 nonce 往返/源年龄证据，保留远端原值。不同时间域不得混排。
4. 新回放时间轴至少覆盖采样帧和主机已接收的任务/决策/执行事件，使执行阶段无新神经批次时也可回看。播放只依据档案时间，禁止实时 noVNC 混入；上一/下一步也使用同一游标。只持有当前帧及有界缓存。
5. 在游标时刻只显示当时已经归档产生的最后一个遥测批次，不选未来批次；其时间龄超过阈值则标为“上一批”，不插值脉冲。帧使用同理的向后匹配，超过登记间隔或已记录 gap 时显示“此处未采集”，不能把一张旧图当持续实时画面。
6. 按神经批次查看仍可作为旧档案路径，但新的回放不能只以批次索引替代主机时间。回放标识保持可见，失败轮也可回看；单张图和真实 MC/odom 原始证据分别承担各自证据角色。

## 失败、关闭与安全边界

| 情况 | 最小行为 |
|---|---|
| 候选缺失、身份不符、wave 未具备资格 | 沿现有门槛拒绝/显示原因；录制功能不能开放能力或回退旧模型 |
| noVNC 断开、页面加载失败或捕获空图 | 记录画面缺失/错误，不沿用上一张冒充新帧；现有控制保护仍独立运行 |
| 正式资格运行写盘失败、采样超预算 | 明确档案失败，停止新采样，并通过现有独立停止入口请求结束本轮；不能因采样错误挂住停车或悄悄丢掉证据继续宣称通过 |
| 用户普通结束互动 | 仍只发送 END_INTERACTION 给脑；采样记录它是否产生正确停止，不能调用保护替它完成 |
| 紧急停止/关闭窗口/renderer 退出 | 立即沿现有 controller.stop 请求保护；同时禁止新 capture。停车/VM 清理优先，不等待编码或写图才发停止 |
| capture Promise、写入或封存迟迟未返回 | 封存最多额外有界等待（建议 2 秒），超时保留 incomplete；晚到结果受 session generation guard 隔离，不写入下次 run。不能为了录像延迟既定控制清理期限 |
| 资源已关但档案不完整 | 可以报告记录失败，不改写机器人安全状态；是否能关窗仍以原安全清理确认判据为准。不得把“录像封存完成”等同于“机器人停止” |
| 控制停止/资源清理未确认 | 保留现有失败窗口与原始证据，不允许一键自动新实验；恢复先解决清理状态，重新开始必须创建新 run，不恢复旧在途动作 |

图片只来自已隔离的仿真 WebContents，不采集用户整屏。保持 `nodeIntegration=false`、sandbox、权限/导航/弹窗/下载限制；不用 `file://`、任意动态资源路由或解除 CSP 来显示图片。可通过受限 IPC 返回有界 JPEG，再使用现有 `img-src data:` 显示；逐张释放/替换引用即可。

画面录制无权修改 task、decision、feedback 或成功计数；读取和回放不会启动脑、VM、设备。不要把失败轮自动切成成功录像，不能把旧模型脑活动和新动作画面拼成同次 run。

## 与风险相称的必要验证

本报告为 S0，仅阅读已有文件和官方 API、检查新增文档；未执行验证程序。后续 M5a 因涉及跨 Electron 主进程/renderer 档案读取、IPC 和关闭生命周期，按 S3 审查边界，检查仍只覆盖桌面子系统。

1. 一个定向 Node 测试入口：注入捕获/时钟/文件失败，覆盖单在途采样、额度与 gap、跨 run/身份错配/目录或符号链接越界、未封存档案、关闭期间迟到帧；沿用既有控制器安全关闭与旧记录兼容用例。不得用假图测试成功代替实际采样。
2. 如修改 TypeScript/渲染入口，运行一次现有桌面构建（包含类型检查），不做全仓测试或重复 lint。
3. 在训练结束、M2/M3/M4 对应准入满足且协调者登记资源后，将一次短原生桌面采样验证合并进必要的 M4 运行：确认画面对应真实运动、主机时间关系、资源开销、停止后封存；记录实际帧间隔、遗漏、capture 时延和磁盘量。不为录像另开第二个完整脑或 CPU 仿真。
4. 仿真关闭后用同一档案验证回放左侧图与右侧同 run 遥测、动作中无新批次阶段、缺帧提示、旧无画面记录和关闭行为；不能通过启动实时仿真补齐回放。
5. 新的独立验收者核对已有结果、来源关联与边界，不机械重跑通过的检查。工程通过只标 M5a；P5 的 25 次任务和 M6 的现场 30 次任务仍按原门槛计分。
