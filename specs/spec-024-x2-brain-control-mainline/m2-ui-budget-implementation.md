# M2 UI 准备预算修复实施

日期：2026-10-23。风险 **S1**，仅调整独立技能 host 的有限准备预算及登记，不改变技能或官方组件。

## 原因与范围

第三轮 `data/x2_sim/agibot/data/var/skills-20261023-143217-57b4dc21` 在官方 UI 准备的 80 秒等待内超时，`probes=[]`、`resources_stopped=true`。本次针对 CUA 界面观察和工具往返占用准备时间的问题；不将该超时记作技能失败，也不修改动作成功标准。

仅修改 `src/malecns_lab/experiments/x2_skill_host.py`，新增直接 CPU 检查 `tests/test_x2_skill_budget.py`，以及本报告。旧 run 和源快照保留。

## 修改

- 增加 `--ui-timeout` 与 `--wall-timeout`；仅允许 `(80, 240)` 和 `(180, 360)` 两组秒数。默认仍为 80/240，CLI 和运行对象构造器均拒绝混配、其他数值、NaN 和无穷值。清理预留固定 30 秒，不能由 CLI 调小。
- 新一轮可显式增加 `--ui-timeout 180 --wall-timeout 360`。这是后续运行参数，**本次未运行仿真命令**。
- UI 实际截止仍取 `min(工作截止 − 60 秒, UI 开始 + 指定等待)`；保留原有 UI 后的 60 秒余量及 30 秒清理窗口。若启动已消耗墙钟，UI 等待会被总预算收紧，不保证始终获得完整 180 秒。
- `ready.json` 和等待状态记录实际 UI 单调截止；所有 host 状态及 `host_summary.json` 记录 UI 上限、有效总墙钟、清理预留、UI 后余量及工作/清理单调截止。预览也显示所选预算。
- 原四参数构造仍有效，新预算为仅关键字参数。预算记录从实际 `deadline()` 推导，因此 M4 的继承类继续使用自身的截止实现，不误登记为 240 秒；M4 默认 UI 等待仍为 80 秒。
- 每技能原 40 秒上限、启动下一技能前至少 41 秒余量、任一 probe 失败停止后续、停止和清理逻辑均保持原样。增加准备预算不保证五项技能都有时间运行。
