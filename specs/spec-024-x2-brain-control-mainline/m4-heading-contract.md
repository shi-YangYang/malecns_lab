# M4 方向任务的目标与实际朝向

状态：准备实施。当前bridge把heading_error_rad固定为0，会把FACE_LEFT/RIGHT错误描述为已经对齐；本补充定义可核对的请求目标，保留M1输入schema与既有三头控制边界。

- 每个新的FACE_LEFT/RIGHT request，在第一份有效、未过期的实际里程计快照时记录起始yaw。左任务请求相对+0.45rad，右任务请求相对−0.45rad；目标绝对yaw按角度环绕计算，绑定run/session/request以及建立时的远端观测序号/时刻。
- 后续heading_error_rad始终由固定目标减当次实际yaw并环绕到[−pi,pi]计算。同一request的轮询、gate-only刷新和实际入脑不得移动目标；同任务新request建立新目标。MC报告动作完成不得直接把误差置0。
- 目标是明确的用户任务几何意图，不是传感器观察到的人或摄像头目标。不声称视觉感知/人物跟踪；其来源与目标、起始yaw、当前yaw、原始里程计和误差分别归档。非方向任务没有朝向目标，现有0误差代表该任务不要求朝向，不宣传已追踪目标。
- 这层只生成脑的观测输入和可审计目标，不提交行为/速度/MC命令，不调用teacher，不替脑决定转向、挥手或任务成功。实际执行仍由脑的三头与已审查gate选择。
- 现有离线教师在收到一次转向COMPLETED后可能转为挥手，因此本补充不能独自证明达到0.45rad目标。后续实际资格记录必须同时报告净转向、剩余目标误差及原始脑选择，不能将有方向运动等同准确对齐。专项数据/模型若需要目标精度改进另立新身份，不改写本轮baseline数据。
- 对无效/过期里程计不建立目标、不用伪造yaw；继续采用已有缺反馈/保护路径。目标metadata由transport明确携带，身体反馈保持同源年龄；拒绝反馈叠加时保存本次真实身体与目标证据，不挪用旧request的目标。

实施限定在M4 session/bridge与直接轻量检查，不改M1编码/已登记M3源或模型，不启动仿真/脑。由新独立验收核对目标固定性、正负与环绕、同任务新request、无效反馈和执行完成不伪造归零，再准入实际联调。
